# Parameters and profiles

The controller keeps its settings in twelve registers (0x9021 to 0x902C). The daemon polls them as the `parameters` block, `solarlife read parameters` shows them, and `solarlife write NAME=VALUE` changes single values. A **profile** is a named set of these values that can be saved to a file and loaded back.

## The parameters

The table lists the accepted values exactly as `solarlife write` takes them (case does not matter). Numbers are volts in steps of 0.01. The protocol does not document which ranges the device accepts, so none are listed here: the device may reject values outside its limits, and `profile load` reports that as a failed write or a read-back mismatch. Which settings matter depends on the battery type, see the descriptions.

| Name | Address | Unit | Accepted values | Description |
| --- | --- | --- | --- | --- |
| `battery_type` | 0x9021 | - | `Lithium`, `Liquid`, `GEL`, `AGM` | Battery chemistry the charging algorithm is set up for. |
| `low_voltage_protection_voltage` | 0x9022 | V | number (V), steps of 0.01 | Battery voltage at which the low-voltage protection triggers. |
| `low_voltage_recovery_voltage` | 0x9023 | V | number (V), steps of 0.01 | Battery voltage at which the controller recovers from the low-voltage protection. |
| `boost_voltage` | 0x9024 | V | number (V), steps of 0.01 | Boost (strong) charging voltage. Lead-acid battery types. |
| `equalizing_voltage` | 0x9025 | V | number (V), steps of 0.01 | Equalizing charge voltage. Lead-acid battery types. |
| `float_voltage` | 0x9026 | V | number (V), steps of 0.01 | Float charge voltage. Lead-acid battery types. |
| `system_rated_voltage_level` | 0x9027 | - | `Auto`, `12V`, `24V`, `36V`, `48V`, `60V`, `110V`, `120V`, `220V`, `240V` | Rated system voltage; Auto lets the controller detect it. |

The same list is available from the CLI: `solarlife variables --writable --block parameters`.

## Profile files

A profile is a YAML file:

```yaml
name: my-battery            # optional, defaults to the file name
description: 12 V AGM       # optional
values:
  battery_type: AGM
  system_rated_voltage_level: 12V
  boost_voltage: 14.4
  float_voltage: 13.6
```

- Only the twelve parameters above are allowed. Protected registers (slave id, baud rate, password, restore and clear commands) can not be part of a profile.
- A profile may list only some of the parameters; the others are left alone.
- Values are checked with the same rules as `solarlife write`, so a typo is an error before anything is sent.
- YAML reads `On` and `Off` as true and false; both spellings work for `mt_series_manual_control_default`.

## Commands

```
solarlife profile list                       # premade profiles
solarlife profile show agm-12v               # print one
solarlife profile save before.yml            # save the device's current parameters (read live)
solarlife profile diff agm-12v               # what would change
solarlife profile load agm-12v               # diff, ask, write, read back
solarlife profile load ./before.yml --yes    # restore without asking
```

`NAME` is a premade profile; a reference that contains a `/` or ends in `.yml` or `.yaml` is a file (write `./name.yml` for a file in the current directory).

`profile load` always compares with the live values first and writes only the values that differ. It then reads the parameters back and fails with exit code 1 if the device reports anything other than what was written. Without `--yes` it asks on a terminal and refuses to run without one. `--dry-run` stops after the comparison, same as `profile diff`. `profile save` refuses to overwrite a file without `--force`; `--cached` takes the daemon's cached values instead of reading live.

To go back after an experiment: `solarlife profile save before.yml`, change things, `solarlife profile load before.yml`.

The device silently ignores some writes. On a controller set to `GEL`, writing `charge_recovery_voltage_for_lithium` was accepted without an error but the value stayed unchanged, while `equalizing_voltage` took effect. The lithium voltages most likely only apply when `battery_type` is `Lithium`; to switch a controller to a lithium battery, load the profile with `battery_type` included (the premade lithium profile does) and check the read-back. A value the device ignored is reported as a mismatch and exit code 1.

Changing `battery_type` may make the controller reset other voltages on its own. The read-back after a load shows what the device really ended up with; if values are off, load the profile again.

## Premade profiles

These are starting points for 12 V systems. **The voltages are typical values and not a recommendation for your battery: check them against its datasheet before loading.**

| Name | Battery type | Low voltage protection / recovery | Boost | Equalizing | Float | Lithium target / recovery |
| --- | --- | --- | --- | --- | --- | --- |
| `lead-acid-flooded-12v` | Liquid | 10.8 / 12.2 V | 14.4 V | 14.6 V | 13.8 V | - |
| `agm-12v` | AGM | 10.8 / 12.2 V | 14.4 V | 14.4 V | 13.6 V | - |
| `gel-12v` | GEL | 10.8 / 12.2 V | 14.2 V | 14.2 V | 13.8 V | - |
| `lifepo4-4s-12v` | Lithium | 11.2 / 12.4 V | - | - | - | 14.2 / 13.4 V |

All of them also set the system voltage level to `12V`. They leave the 0 °C charging behaviour and the MT series load settings alone.
